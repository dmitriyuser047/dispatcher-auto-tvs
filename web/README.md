# Веб-диспетчер ТВС

Многостраничный диспетчер для Windows и доверенной локальной сети. Оформление — выбранное синее стекло с локальным шрифтом Onest и кириллицей. Для локальной сети домен не требуется. Инструкция и PowerShell-скрипты находятся в `deployment/windows/`.

## Установленная программа

Папка программы — `E:\DispatcherWeb`. Запуск — `Запустить.cmd`: сервер работает в фоне, повторный запуск открывает существующий экземпляр. Закрытие окна запуска не останавливает сервер. На текущем компьютере настроена автозагрузка через ярлык «Диспетчер ТВС» в папке автозагрузки пользователя serge: скрытый `config/launch/autostart.vbs` вызывает штатный запуск с `--no-open`. Сервер включается при входе в Windows. Запуск до входа требует отдельной настройки с правами администратора.

Защищённый `config/server.json` содержит абсолютные пути `dataDir`, `usersFile`, `stateDir` и порт `port`. База остаётся по указанному пути; программа её не перемещает. `state` предназначен исключительно для очереди операций, журналы запуска находятся в `config/launch`. Конфигурация, персональные ключи, база и резервные копии не публикуются как файлы сайта.

Перед запуском проверяются текущая схема SQLite и резервный ZIP. Перед новым сохранением резервирование остаётся обязательным. Старую схему этот запуск автоматически не мигрирует.

Распределение счетов выполняется в разделе «Реестры» кнопкой «Распределить». После сохранения все автомобильные счета отображаются в общем блоке «Ремонты и ТО» карточки авто, счета ДЭС — в карточке ДЭС, счета водителей — в их карточках. На карточках нет действий повторной привязки. Отдельная запись ремонта или ТО для отображения счёта не нужна. В реестре дополнительно можно указать конкретные работы; ссылка `serviceRef` сохраняет корень документа при исправлениях. Номер, введённый вручную в ремонте, остаётся текстом и не считается связью с реестром. Распределение не создаёт ремонт, расход или оплату и не меняет их суммы.

При распределении поставщики из реестров добавляются в «Контрагенты» в той же атомарной операции. Существующая уникальная карточка используется по нормализованному названию; неоднозначные одноимённые организации автоматически не объединяются. Новые ИНН, контакты и телефоны не выдумываются. Счета сохраняют типизированный `contragentId`; переименование справочника не меняет напечатанного поставщика. В справочнике показаны число счетов и сумма по реестрам отдельно от учётных расходов и долга. Связанная карточка архивируется с сохранением истории. Совместное сохранение требует прав на нужные разделы и запрещает автоматическое слияние при конфликте версий.

В топливной аналитике распределённые пробег и нормативный расход суммируются как точные десятичные значения. Если промежуточный результат не представим JavaScript-числом без потери точности, он сохраняется десятичной строкой для таблицы и Excel. Денежные правила и исходные журналы не изменяются.

«Финансы» (`/finance`) показывает статистику реестров по месяцам, статьям БДДС, автомобилям, ДЭС, водителям, организациям и объектам. Счёт считается один раз в общем количестве, распределённые суммы суммируются в точных копейках; неизвестные суммы делают итог неполным. Период определяется датой счёта с резервной датой реестра. Факт оплаты из наличия счёта не выводится. «Расходы и бюджет» (`/finance?view=expenses`) использует те же счета, показывает список и сравнение со внесёнными планами по периоду и статье. Отсутствующий план обозначается «План не задан», явный нулевой план остаётся нулевым. Планы без статьи не распределяются по расходам автоматически; при неполном плане общее отклонение не вычисляется. Прежние ручные финансовые записи доступны на `/finance?view=ledger`, ввод бюджета — через кнопку «План бюджета» и `/finance?view=ledger&mode=budget`. Статьи БДДС берутся из существующего `ReestrBuilder/statyi.json`; в реестрах и фильтре статистики их можно искать по коду или названию. Исторические статьи сохраняются.

Для работы только на сервере используется `host: "127.0.0.1"`. Для локальной сети скрипт `deployment/windows/Configure-Dispatcher.ps1 -Lan` устанавливает `host: "0.0.0.0"` и точный список разрешённых имён/IP. Он проверяет базу, учётные записи и резервный пакет до замены конфигурации; предыдущая конфигурация сохраняется. Скрипты не изменяют брандмауэр, маршрутизатор и автозапуск. Адреса сотрудников выводит `Start-Dispatcher.ps1`.

Каждый сотрудник входит по персональному ключу. Администратор на `/settings/users` создаёт доступы, меняет роли, отключает сотрудников и перевыпускает ключи. Открытый ключ показывается один раз; файл `config/users.json` хранит хэши. Права и отзыв ключа проверяются заново при запросах. Самоотключение и удаление последнего администратора запрещены. Используйте отдельный ключ для каждого сотрудника.

## Страницы

Разделы открываются отдельными HTML-документами по обычным ссылкам. Обновление страницы и переходы браузера сохраняют выбранный экран; `history.pushState` для смены раздела не используется.

В самостоятельном разделе «Реестры» (`/registries`) загружаются реестры XLSX/XLS и PDF с текстовой таблицей и границами столбцов. В Excel можно выбрать лист, строку заголовков и соответствие столбцов. PDF с развёрнутыми назначениями платежей читается по строкам таблицы, а не по всем встречающимся в тексте суммам. Перед сохранением сверяются реквизиты, суммы счетов и итог исходника. Для сканов PDF требуется распознанная копия или Excel. Прежний адрес `/documents/invoices/import` открывает раздел «Реестры». «Логистика» (`/logistics`) имеет собственную страницу без загрузки реестров.

Каждый счёт относится к автомобилю, ДЭС, водителю, прочим платежам либо остаётся неразнесённым. В счёте есть прямое поле «Водитель по счёту»: выбирается точная карточка сотрудника. Обучение и одежда показаны как виды счёта. В карточке водителя раздел «Счета» показывает связанные документы с переходом к нужному счёту в реестре; части одного счёта объединяются в одну запись. Отдельной вкладки расходов на водителей в реестрах нет. Счёт можно разделить на несколько получателей затрат; копейки должны сходиться с суммой счёта. Оригинал сохраняется в защищённом архиве, данные — в `savedReestrs` общей базы с принадлежностью `workspace: "registries"`. Загруженные реестры показаны в собственном списке и не смешиваются с сохранёнными документами распознавания счетов. Повтор того же файла блокируется; повтор счёта требует отдельного основания. Сохранение использует штатные права, резервную копию, проверку версий и очередь операций. Сам импорт не создаёт факта оплаты, ремонта или списания. По счетам доступны фильтры и выгрузка распределения в Excel.

На `/maintenance` перенесён мастер ТО из Electron 3.5.23: выбор ДЭС по организации и объекту, настройки нескольких видов обслуживания в карточке, создание годового графика по заданным плановым часам, сохранённые редакции и отдельная печать графика и ЗИП. Вложенное окно настройки остаётся поверх списка ДЭС. Выбор техники и расчёт не записывают фактическое обслуживание и не меняют склад. Используются те же контроллеры и правила сохранения, оформление соответствует синему стеклу веб-версии.

Раздел «ДЭС» содержит объекты. В разделе «Транспорт» автопарк и журнал пробега открываются отдельно. Объектный фильтр ДЭС не ограничивает общую сводку транспорта.

Общий шаблон сохраняет формы и контроллеры настольного приложения, расчётные модули `assets/core`, связи документов и существующие проверки. Рабочие страницы получают полные текущие разделы без многомегабайтной истории аудита. История загружается отдельно для соответствующих экранов и перед сохранением, когда нужен полный исходный снимок. Ограниченные права используют полный проверенный путь чтения. Кеш проекций проверяет свежие исходные SQL-байты; права, версии и идентификатор базы проверяются при каждом чтении.

Одновременно ожидающие запросы с одинаковой ролью и правилами доступа получают общий свежий снимок, прочитанный после формирования группы. В группе не больше 64 запросов; общая очередь ограничена 512. Пользователь, права и профиль совместимости формируются отдельно для каждого ответа. Отправка проходит синхронно под блокировкой базы после повторной проверки доступа. Новые запросы создают следующую группу; предыдущий снимок для них не используется. Чтение истории, ограниченные учётные записи и старые форматы обслуживаются отдельно.

Начальные сведения и последующая проверка контекста кеша также читают свежие служебные данные группами. Вход проверяет персональный ключ; согласование права записи выполняется перед самой записью. При поддержке браузером gzip каждый ответ сжимается в один поток до завершающей проверки доступа и отправки. Файл сотрудников перечитывается при каждой проверке: повторно используется только проверка полностью совпадающих байтов, а изменение прав и истечение срока администратора проверяются заново.

## Документы и файлы

| Возможность | Работа в браузере |
| --- | --- |
| JSON, Excel и контролируемые импорты | Браузер выбирает файл; исходные байты передаются штатным стадиям импорта |
| PDF-сводки, ГЛОНАСС PDF/Excel, RAR | Сервер использует существующие декодеры и проверяемые стадии импорта |
| OCR | Серверное распознавание с поставляемыми моделями |
| Печатные формы | Реальные PDF формируются в отдельном скрытом процессе из `runtime/electron` |
| Инвентаризация | Формирование PDF и XLSX с контрольной суммой результата |
| Вложения | Загрузка и скачивание с проверкой прав на исходную запись и резервированием перед сохранением |
| PDF-студия | Просмотр, редактирование, объединение, изображения, проекты, восстановление и экспорты на отдельной странице |
| Выгрузки Excel | Штатный `vendor/xlsx.bundle.js` и серверные экспорты |

Загрузки проверяются по размеру и SHA-256 перед скачиванием. Серверные пути не передаются в браузер. Редактор хранит временные файлы отдельно по сеансам и удаляет их после закрытия сеанса.

Сертификаты, резервные пакеты, ремонт базы, смена каталога и настройки сервера выполняет администратор на Windows. Трей, уведомления Windows и установщик настольных обновлений не являются браузерными операциями. Недоступная операция показывает ошибку; успешное сохранение не имитируется. Ошибка первоначальной загрузки никогда не переключает приложение на пустую локальную базу.

## Доступ и сохранение

Браузер работает через `/web-api` на том же адресе. Внутренний API `electron/server.js` слушает отдельный loopback-порт и не принимает браузерный Origin. Персональный ключ и разрешение записи остаются в процессе сервера; браузер получает случайную HttpOnly/SameSite=Strict cookie и CSRF-токен. Ключ не хранится в localStorage.

Записи проходят прежние проверки схемы, прав, версий, операций и конфликтов. Бизнес-запись не повторяется автоматически при сбое связи. Состояние ожидающих операций сохраняется в отдельной очереди; неоднозначный результат проверяется по исходной операции. Перезапуск завершает веб-сеансы, очередь сохраняется.

LAN-конфигурация использует HTTP в доверенной частной сети и точный список разрешённых Host/Origin. Внешний публичный адрес, HTTPS, домен и служба Windows требуют отдельной настройки и не включаются локальным запуском.

## Сборка и проверка разработчиком

Из проекта с уже установленными зависимостями и Node.js 24:

```powershell
node scripts/prepare-web-deployment.cjs --target 'E:\DispatcherWeb' --with-pdf --protected-path 'C:\Absolute\WorkingDatabase'
```

Папка назначения должна быть новой или пустой. Помощник копирует производственные зависимости, Node.js и полный Windows Electron runtime без сети, баз и персональных ключей. Существующая программа не перезаписывается. Только `electron.exe` без DLL и ресурсов недостаточно для PDF.

Демо с отдельной синтетической SQLite и случайным ключом:

```powershell
node web/cli.cjs --demo --port 3380
```

Каждый демо-запуск создаёт отдельные данные в `web/.local/demo-*`; рабочая база не используется. Остановка прямого запуска — Ctrl+C.

Прямой запуск установленной конфигурации:

```powershell
node web/local-runtime.cjs --config 'E:\DispatcherWeb\config\server.json'
```

Веб-проверки и отдельная синтетическая нагрузка:

```powershell
npm run test:web
node scripts/web-load-check.cjs --workspace --writes
node scripts/web-load-check.cjs --startup --disk-users --concurrent-login --keepalive --gzip --writes
```

Нагрузочный прогон создаёт временную SQLite с 52 машинами и более 2000 учётных строк, выполняет вход 150 пользователей и 150 параллельных чтений. `--workspace` проверяет рабочую загрузку, без него — полный снимок. `--writes` добавляет десять параллельных правок с общей исходной ревизией: конфликтные изменения не повторяются автоматически. После прогона временные данные удаляются.

`--startup` проверяет параллельные bootstrap/workspace и следующий свежий ping: всего 450 GET для 150 сеансов. `--disk-users` использует настоящий загрузчик отдельного синтетического файла учётных записей; `--concurrent-login` выполняет входы одновременно. `--keepalive` даёт каждому пользователю отдельный пул до шести соединений с повторным использованием соединения входа; 150 пользователей продолжают работать параллельно. `--gzip` включает штатное согласование сжатия и выводит размеры переданных и распакованных данных отдельно. Без этих флагов исходный тест сохраняет прежний режим для сравнения.

Строгий режим без keep-alive создаёт новое TCP-соединение для каждого запроса. На проверенном настольном Windows даже пустой сервер Node.js принял 232 из 300 одновременных новых соединений; остальные получили ECONNREFUSED. Увеличение положительного backlog это ограничение не сняло. Нагрузку новых подключений следует отдельно проверять на выбранном сервере; результаты загрузки данных через уже установленные браузерные соединения не подтверждают пропускную способность при таком всплеске.

Требование — больше 100 сотрудников. Прогон с синтетическими учётными записями в памяти измеряет конкретную нагрузку, но не подтверждает производительность дисковых политик, длительной работы или SLA. SQLite последовательно выполняет записи; часть старых форм сохраняет целые разделы. Для изменений расчётных и учётных контрактов дополнительно используются соответствующие существующие тесты проекта.

## Общая версия с настольным приложением

В этой ветке веб-экраны используют тот же слой `src/application`, команды карточек и правила расчётов, что настольная программа. Отложенные разделы догружаются перед сохранением с повторной проверкой базы и прав; неподтверждённый ответ не устанавливается как успешное изменение карточки. Реестры, распределение счетов, статистика, бюджет и связанные счета доступны также в настольных разделах.

Суточные открываются через «Водители» → карточка → «Суточные». Для поездки явно задаются даты, ставка, правило оплаты дней, основание и аванс. Долю дня или исключение можно указать с пояснением. Расчёт показывает начислено, доплату или возврат; поездки можно отменить с сохранением истории и выгрузить в Excel. Автоматической выплаты или финансовой проводки не создаётся. Утверждённую ставку вводит пользователь. Подробности: `../docs/driver-per-diem.md`.

Изменения исходников сами по себе не обновляют установленный веб-сервер или настольную программу. Выпуск и установка выполняются отдельно.
