# Веб-диспетчер на Windows в локальной сети

Эти скрипты входят в автономную папку программы. Для `E:\DispatcherWeb` они находятся в `E:\DispatcherWeb\app\web\deployment\windows`. Используется её `runtime\node.exe`; установка Node.js, npm или доступ к интернету не нужны. Скрипт настройки сохраняет конфигурацию только после проверки существующей SQLite-базы, персональных учётных записей и резервного пакета. База не переносится и не создаётся заново.

## Сборка папки с формированием PDF

На компьютере сборки, где зависимости проекта уже установлены, включите штатный Windows Electron runtime:

```powershell
node scripts/prepare-web-deployment.cjs --target 'E:\DispatcherWeb' --with-pdf --protected-path 'E:\DispatcherData'
```

Новая или пустая папка назначения получает Node.js, производственные зависимости и полный `runtime\electron` с DLL, ресурсами, локализациями и манифестом SHA-256. Исходный Electron берётся из установленного `node_modules\electron\dist`; файлы не загружаются из сети. Если дистрибутив Electron отсутствует или неполон, сборка прекращается до создания папки назначения. Копирование только `electron.exe` не заменяет полный runtime.

Для уже подготовленной папки программы с отсутствующим `runtime\electron` можно отдельно подготовить этот новый или пустой каталог:

```powershell
node scripts/prepare-web-pdf-runtime.cjs --target 'E:\DispatcherWeb\runtime\electron'
```

Эта команда выполняется из исходного проекта на компьютере сборки. При необходимости `--source 'C:\Absolute\Electron\dist'` задаёт другой уже имеющийся Windows-дистрибутив. Существующие непустые папки не перезаписываются. На сервере для формирования PDF используется скрытый процесс из папки программы; запуск настольного интерфейса сотрудникам не нужен.

## Подготовка сервера

1. Разместите подготовленную папку программы на локальном диске Windows. Сохраните отдельно существующую рабочую базу текущего формата и файл персональных учётных записей. Одна учётная запись с отдельным ключом нужна каждому сотруднику; права записи задаются для пользователя. Создание и проверка этих записей описаны в `app\web\README.md`.
2. Каталоги `config`, `state`, рабочей базы, журналов и резервных копий должны быть доступны только администратору и Windows-пользователю, запускающему сервер. Сотрудникам нужен доступ через браузер; общая файловая папка с базой или ключами им не нужна. Не размещайте приватные файлы в `assets`, `vendor` и `web\public`. `state` предназначен только для очереди операций; журналы запуска находятся в `config\launch`.
3. Для постоянного адреса закрепите частный IPv4 сервера в настройках локальной сети. Используйте доверенный профиль сети Windows «Частная» либо корпоративную сеть. Веб-доступ в этой конфигурации использует HTTP и предназначен для доверенной локальной сети; не используйте его через публичный Wi-Fi.

Сначала настройте запуск только на сервере; замените пути на реальные:

```powershell
& 'E:\DispatcherWeb\app\web\deployment\windows\Configure-Dispatcher.ps1' `
  -DataDir 'E:\DispatcherData' `
  -UsersFile 'E:\DispatcherWeb\config\users.json'
```

Без `-Lan` сохраняется `host: "127.0.0.1"`. Если конфигурация уже существует, параметры базы, учётных записей, очереди, резервных копий и порта сохраняются, если не передать их явно. При повторной настройке работающий сервер нужно предварительно остановить обычным способом; новые параметры применяются после перезапуска. Скрипт не останавливает чужие процессы.

## Включение локальной сети

Когда база и персональные учётные записи уже указаны, выполните:

```powershell
& 'E:\DispatcherWeb\app\web\deployment\windows\Configure-Dispatcher.ps1' `
  -Lan -TrustedHost 'DISPATCHER', '192.168.1.20'
```

Это включает `host: "0.0.0.0"` и добавляет перечисленные имена/IP в `allowedHosts` вместе с `localhost` и `127.0.0.1`. Укажите реальное имя компьютера и его частный IP, без `http://`, порта и пути. Если `-TrustedHost` не передан, скрипт использует имя компьютера и обнаруженные частные IPv4 активных интерфейсов. Проверьте показанные адреса, особенно если у сервера несколько сетевых карт или VPN. Явный список предпочтителен для постоянного рабочего сервера.

Параметры `-Port`, `-StateDir` и `-BackupDir` позволяют выбрать отдельный порт, каталог очереди и каталог резервных пакетов. Пример JSON находится рядом в `server-config.example.json`. Адрес `0.0.0.0` служит для прослушивания интерфейсов; сотрудники открывают имя сервера или его частный IP из списка адресов.

Проверка перед сохранением создаёт или проверяет ежедневный резервный пакет выбранной базы. При её ошибке прежний `config\server.json` сохраняется. При успешной замене прежняя конфигурация остаётся рядом под именем `server.*.previous.json`. Удаление старых конфигураций и перенос резервных пакетов на отдельный носитель выполняет администратор по принятому порядку хранения.

## Запуск и проверка с рабочего компьютера

```powershell
& 'E:\DispatcherWeb\app\web\deployment\windows\Start-Dispatcher.ps1'
```

Для запуска без открытия браузера добавьте `-NoOpen`. Скрипт использует штатный launcher: сервер запускается в фоне, повторный запуск открывает уже работающий диспетчер. После перезагрузки Windows запустите скрипт снова. Автозапуск и служба Windows этими скриптами не создаются.

После сообщения о готовности:

1. На сервере откройте показанный локальный адрес и войдите со своей персональной учётной записью.
2. На другом компьютере той же локальной сети откройте, например, `http://192.168.1.20:3381/objects`. Проверьте отдельный вход второго сотрудника и соответствие его прав. Для проверки записи используйте согласованную тестовую запись либо копию рабочей базы.
3. Если соединения нет, проверьте адрес, подключение к одной сети, профиль сети Windows и разрешения входящих подключений. Если правило требуется, администратор может разрешить только выбранный TCP-порт в профиле «Частная» и ограничить удалённые адреса фактической подсетью сотрудников. Скрипты не меняют брандмауэр или маршрутизатор. Не включайте проброс порта, UPnP и публичный доступ.
4. Если страница вернула отказ для имени сервера, добавьте именно это имя в `-TrustedHost`, повторите настройку и перезапустите сервер. Не используйте wildcard. Если вход или запись не проходят, проверьте персональную запись и журнал; не заменяйте её общим ключом.

Для возврата к работе только на сервере запустите `Configure-Dispatcher.ps1` без `-Lan`, затем перезапустите сервер. Доступ через интернет и HTTPS требуют отдельной согласованной настройки и в этот пакет не входят.
