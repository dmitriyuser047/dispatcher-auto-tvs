# Резервные копии по частям

Ежедневная копия текущей базы создаётся в фоне. Перед сохранением программа фиксирует согласованные разделы, их версии и точку истории. Сами исторические объекты проверяются и упаковываются отдельным исполнителем после снятия блокировки базы. Новые записи могут сохраняться, пока копия собирается.

Копия состоит из двух элементов рядом друг с другом:

- `data_ГГГГ-ММ-ДД.zip` — индекс копии;
- `data_ГГГГ-ММ-ДД.zip.parts` — папка с её частями.

**При переносе копируйте ZIP и одноимённую папку `.parts` вместе.** Для проверки и восстановления в программе выбирайте ZIP. Переименовывать только один из этих элементов нельзя. Каждый индекс указывает на конкретные части и проверяет их контрольные суммы; потерянная, лишняя или повреждённая часть не принимается за полную копию.

Программа публикует ZIP только после сборки и проверки всех частей. Статус «Копия собирается в фоне» означает, что новая копия ещё не завершена. Ошибка копирования видна в состоянии резервирования; ранее завершённые копии сохраняются. Ошибка фоновой упаковки истории не превращает подтверждённое сохранение записи в ошибку и не оставляет его ждать архив.

После перезапуска незавершённое задание продолжает ту же резервную точку. При изменении исходного документа, необходимого старому заданию, ошибочный черновик сохраняется для проверки, а следующая попытка может зафиксировать новую точку. Неопубликованные части после прерывания сохраняются отдельно и не мешают повторной сборке.

История не имеет общего предела 256/512 МБ в новом формате. Размер отдельной части ограничен 32 МБ распакованных данных; объекты истории проверяются по отдельности. Проверка и восстановление используют ограниченную память и не собирают всю историю в один объект. Для индекса и отдельных файлов остаются проверки формата, путей и размеров. Нехватка места или повреждение данных показываются как ошибка копии.

Восстановление выполняется в отдельную новую папку SQLite либо JSON с сохранением разделов, версий, событий и квитанций. Существующая рабочая база не перезаписывается. Прежние резервные пакеты форматов 1–3 продолжают читаться.

Служебные точки отката перед подтверждённым обменом ДЭС создаются полностью до применения обмена. Эта явная операция ждёт готовую копию; общий объём истории также не ограничивает её одним архивом.

Проверки разработки выполняются на отдельных базах: потоковая история свыше 512 МБ, восстановление с ограничением памяти, сохранение другим процессом во время упаковки, прерывание и продолжение, повреждённые части и повтор уже завершённого восстановления.
