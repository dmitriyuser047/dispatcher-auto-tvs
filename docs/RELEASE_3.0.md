# Обзор выпуска 3.0

Дата проверки: 18 октября 2026 года.

## Исследование официальных источников

| Источник | Применение в проекте |
| --- | --- |
| [Electron: Security](https://www.electronjs.org/docs/latest/tutorial/security/) | Проверка отправителя каждого IPC-запроса, ограничение навигации и новых окон, запрет разрешений по умолчанию, ограничение файлов локального HTTP-сервера. |
| [Electron: Breaking Changes](https://www.electronjs.org/docs/latest/breaking-changes) и [релизы](https://releases.electronjs.org/?channel=stable) | Переход с Electron 28 на стабильный Electron 44.9.0 с проверкой нативных окон на Windows x64. |
| [Mozilla: CVE-2024-4367 в PDF.js](https://github.com/mozilla/pdf.js/security/advisories/GHSA-wgrm-67xf-hhpq) | Замена PDF.js 3 на 6.4.299, переход на ESM, локальные worker и ресурсы шрифтов. |
| [Node.js: File system](https://nodejs.org/api/fs.html) | Запись настроек и снимков через временный файл с flush и последующим rename. |
| [Playwright: Electron](https://playwright.dev/docs/api/class-electron) | Проверка настоящего Electron, IPC, смены базы работающего сервера и нескольких PDF-окон на временных данных. |

Версии пакетов дополнительно сверены с npm при установке. Интернет-источники использованы для технических решений; правила бухгалтерского учёта и утверждённые формы документов этим выпуском не пересматриваются.

## Область изменений

Проверены загрузка и сохранение данных, миграция JSON, сетевой API, конфликты синхронизации, транспорт, ДЭС, ёмкости, ГСМ, импорт, реестры, финансы, печатные формы, отдельные окна документов и механизм выпуска. Сохранены формат базы и прежние бланки актов. Автоматического пересчёта рабочей базы при обновлении нет.

Исправлены преждевременные сообщения об успешном сохранении, повторная запись по двойному нажатию, перезапись одинаковых полей при конфликте, привязка сетевого сервера к старой базе после смены профиля, общий снимок для нескольких PDF-окон и неконтролируемые пути в импортируемых архивах. Добавлены диагностика и ручная резервная копия.

После технической подготовки глобально переработан интерфейс: постоянная навигация, обзор на реальных данных, таблицы транспорта и ДЭС, согласованные панели действий, формы и окна документов. Обе темы проверяются при ширине 960 и 1280 px; широкие учётные таблицы прокручиваются внутри рабочей области. Тема хранится в настройках и применяется к открытым окнам документов.

Для основной программы выбрана палитра «Камень и слива»: молочный фон светлой темы, сливовая боковая навигация и акценты. Тёмная тема использует ту же гамму; цвет текста на кнопках меняется вместе с фоном для сохранения контраста. Окна реестров и PDF используют общие цвета интерфейса; оформление печатных документов не меняется.

Обновления принимаются только из релизов этого репозитория по HTTPS. Установщик проверяется по размеру и SHA-256 до предложения установки и повторно перед запуском. Это проверка целостности; цифровая подпись издателя установщика не добавлена.

## Ограничения и последующая работа

- Проверки включают 82 теста логики/хранения/сети/безопасности, 43 браузерных сценария и интеграционную проверку Electron. Установщик Windows x64 собирается через electron-builder. В CI эти проверки повторяются перед выпуском.
- `npm audit --omit=dev` для основного приложения не обнаруживает известных уязвимостей. В зависимостях инструмента сборки остаётся умеренная уязвимость `sprintf-js`, распространяющаяся по цепочке `@electron/get` → `global-agent` → `roarr`; она не входит в установленное приложение. Принудительный откат сборщика ради подавления отчёта не применён.
- Интерфейс использует общее состояние и inline-обработчики. Политика CSP ограничивает источники, но сохраняет `unsafe-inline` для совместимости. Полная замена UI-архитектуры требует отдельного проекта миграции и не включена в 3.0.
- Сетевой протокол предназначен для доверенной локальной сети и не использует TLS. Для внешних подключений нужен защищённый канал.
- Однопроцессная защита не превращает JSON-хранилище в многосерверную СУБД. Один каталог базы должен обслуживаться одним запущенным сервером; прямое совместное открытие папки с нескольких компьютеров не поддерживается.
- Проверка связей обнаруживает исторические несоответствия, но не удаляет и не исправляет записи самостоятельно.
- Самостоятельные установщики `des-app` и `ReestrBuilder` выпускаются отдельными тегами. В 3.0 обновляется основное приложение.
- Проверки в CI работают с искусственными временными данными. Частные рабочие документы и базы в тесты и релиз не добавляются.
