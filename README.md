# Диспетчер ТВС · единый прототип 3.5.2-prototype.1

Единая тестовая сборка на базе восстановленной 3.5.1: диспетчерская, рабочие процессы, топливный учёт и PDF/OCR объединены с постоянной навигацией и оформлением «Камень и слива». Сохранены светлая и тёмная темы.

Прототип устанавливается рядом с рабочей программой под именем «Диспетчер ТВС — Прототип». Настройки изолированы, исходная папка базы — `Документы/ДиспетчеризацияАвто_ТВС_Прототип`; первый запуск создаёт пустую базу. Встроенная рабочая база не включена. Для испытаний используйте отдельную копию данных: выбор папки в настройках задаёт место записи, а не создаёт копию автоматически.

Автообновления в этой сборке отключены, релизные сценарии отвергают прототип. Сборка создаёт только локальный установщик `dist/Dispatcher-Prototype-3.5.2-prototype.1.exe` и `dist/prototype-manifest.json` с контрольными суммами. `version.json` канала обновлений не переписывается. Ветка: `codex/prototype-unified-3.5.2`.

Проверки: `npm ci`, `npm test`, `npm run test:ui`, `npm run test:electron`. Сборка Windows x64: `node RECOVER-BUILDER-TOOLS.cjs`, затем `npm run build`. Требуется Node.js 22 или новее. Тесты используют синтетические документы и временные базы.

PDF с исключёнными страницами пересоздаётся из видимых страниц с растровой обработкой для удаления скрытых исходных объектов; интерфейс сообщает о преобразовании. Проекты `.tvspdf` сохраняют исходники и предназначены для продолжения редактирования, а для передачи результата используйте экспортированный PDF. Точность OCR на рабочих документах требует отдельной оценки.

## Основа 3.5.1

Восстановленная версия сохранена в ветке `codex/recovered-3.5.1`. Эта ветка предназначена для отдельной сборки и просмотра: канал автообновлений использует `main/version.json`. Выпуск Release и теги для этой версии не создавались.

Сборка в Windows с Node.js 22: `npm ci`, затем `node RECOVER-BUILDER-TOOLS.cjs` и `npm run build`. Установщик появится в `dist/Dispatcher-Setup-3.5.1.exe`. В репозиторий включены готовое собственное ядро, модели OCR и рецепты нативной сборки; кэши компилятора и локальные отчёты в ветку не входят.

Десктопное приложение для учёта автопарка, дизельных генераторов, топлива, обслуживания, финансов и документов ООО «Технрайз Велл Сервис».

## Собственное ядро OCR в 3.5.1

Для OCR собрано собственное ядро Tesseract 5.3.0-tvs1 на базе закреплённых исходников tesseract.js-core 7.0.0. Сборка содержит обычный LSTM, SIMD LSTM и relaxed SIMD LSTM; загрузчик выбирает вариант по возможностям среды и manifest. При загрузке проверяются файлы JS/WASM, набор патчей, API и фактическая строка версии. Происхождение выбранного ядра сохраняется вместе с результатом OCR.

Патчи исправляют передачу настроек словарей в LSTM-декодер и очистку изображения при ошибке чтения. В relaxed SIMD включена отсутствовавшая SSE-реализация резервного пути декодера; существующие математика и переключение режимов сохранены. Также исправлены пути и аргументы Windows-сборки, включена строгая проверка неразрешённых символов и согласованы две пары перегрузок в WebIDL-обвязке. Пять недоступных API legacy/OSD в LSTM-сборке явно выдают ошибку; основной OCR-путь их не вызывает. Происхождение исходников, патчи, лицензии и хэши записаны в vendor/tesseract-core; воспроизводимые рецепты — scripts/ocr-native.

Компиляция и проверка состава файлов не подтверждают качество OCR на документах. Дообучение и функциональная приёмка нового ядра не выполнялись; новые нейросетевые веса в этом этапе не создавались.

## Модели и обвязка, добавленные в 3.5.0

Встроены официальные tessdata_best RU/EN, стандартные модели и отдельные модели без LSTM DAWG для явно выбранных номеров/сумм. Веса производных моделей не менялись: это изменение данных декодера, не дообучение. Происхождение и контрольные суммы записаны в assets/ocr/models-manifest.json.

Исправлена локальная нативная обвязка Tesseract.js: LSTM-only загрузка, статусы ошибок API, нативные деструкторы, очистка изображения и временных файлов. Общий runtime обслуживает реестр и PDF; в PDF доступны Otsu / Adaptive Otsu / Sauvola. В выпуске 3.5.0 .wasm-файлы оставались штатными 7.0.0 (C++-основа fork 5.3.0 по исходникам), а подготовленные C++-патчи ещё не были активированы.

Точный режим может работать медленнее. Улучшение точности, скорость и совместимость новых моделей на рабочих документах не измерены. Для дообучения нужны фрагменты сканов с выверенным текстом и отдельный набор для оценки.

## PDF-студия в 3.4.0

Пакетное OCR, зоны текста и таблиц, сверка сомнительных строк с исходным фрагментом, редактируемая сетка таблиц, экспорт в Word/Excel/TXT/CSV, проекты и восстановление, текстовое сравнение версий и сохранение выбранных PDF-страниц.

Исходный текст изменяется PDF-движком перед записью новых элементов. Сложные страницы и удаление областей сохраняются изображением до 300 dpi с предупреждением; остальные страницы сохраняются векторными. После пересборки закладки, вложения, свойства документа и часть интерактивных форм могут не переноситься. Изменения нарушают действительность старых электронных подписей. Проекты .tvspdf хранят исходные PDF, включая удалённые области: для передачи результата используйте сохранённый PDF.

Word сохраняет редактируемый текст и явные таблицы с приближённой вёрсткой. OCR работает локально через Tesseract; качество и точность вёрстки уровня FineReader не подтверждены. Парольные PDF, сертифицированные подписи, PDF/A/UA и автоматизация папок в этот этап не включены.

Выполнены статический разбор кода, проверка синтаксиса и сборка. Функциональные тесты нового цикла и проверка окна не запускались.

## Что нового в 3.2.0

- Единая визуальная система для всех разделов: меню, техника, топливо, финансы, документы, формы и отдельные окна.
- Диспетчерская: сводка выбранного дня и объекта, расписание, парк по учётным данным, доска и лента суток. F8 включает режим фокуса.
- Распознавание PDF и сканов исправлено; в таблице доступна кнопка «Источник» с извлечёнными полями, строками текста и предупреждениями. Обрабатываются все выбранные ZIP.
- Реальный OCR проверен на синтетических документах, включая смешанные PDF. Латинская T и русская Т могут путаться в номере — сверка с документом остаётся необходимой.

- Ремонтные заказы с приёмкой, простоем и гарантией; документы со сроками и локальными вложениями; склад запчастей и шин с движениями.

- Сравнение произвольных периодов: одинаковая длительность и парк, взвешенные нормы, покрытие фактом, детализация, влияние цены и объёма, Excel. Факт и оценка различаются; нулевой факт сохраняется.
- Импорт транспорта, карт и ГЛОНАСС показывает план до записи; исходные рейсы и версии показаний сохраняются. Возвраты/сторно требуют отдельной сверки, неизвестные товары изолируются.
- Частичная оплата, срок, просрочка, долг, обновление расходов ТО/ремонтов и план–факт; устойчивые ссылки на контрагентов.

- Персональные токены и роли с серверной проверкой, HTTPS с проверкой сертификата, явное разрешение конфликтов полей, история изменений.
- Резервный ZIP содержит базу, вложения, оригиналы импортов, настройки и знания OCR. Проверка SHA256 восстанавливает пакет в отдельную папку.
- Сменные формы передаются JSON-пакетом с предварительной проверкой. Настройки внешних API пока служат спецификацией подключения; реальный обмен требует адаптера поставщика и доступов. Файлы вложений управляются на компьютере основной базы.

## Основа выпуска 3.0

- Оперативная сводка показывает показатели транспорта, журнала за текущий месяц, ДЭС и топливных ёмкостей. В выпуске 3.1.1 она находится в разделе «Диспетчерская → Обзор».
- Очередь внимания собирает сигналы из базы: отрицательные/низкие остатки, заправки без связи с журналом, повышенный расход ДЭС, дубли госномеров, ближайшее ТО и незакрытый месяц. События открывают соответствующие рабочие разделы; учётные данные не меняются автоматически.
- Для ёмкости можно задать минимальный резерв топлива. «Диспетчерская → Обзор» показывает фактическое состояние локальной базы или сетевого соединения и дату последней ежедневной копии.
- `Ctrl+K` открывает поиск по разделам и объектам. Введите госномер, марку, имя ДЭС, ёмкость, контрагента или карту. Стрелки перемещают выбор, `Enter` открывает результат, `Esc` закрывает поиск.
- Поиск сопоставляет `е` и `ё`; пользовательские названия отображаются безопасно.
- Основные рабочие данные хранятся в разделах в папке базы. Система резервного копирования и сетевой синхронизации сохранена.

## Запуск из исходников

Требуются Node.js и npm. После установки зависимостей запустите `npm start`. Чтобы собрать установщик Windows x64, запустите `npm run build`; готовый файл появится в `dist`.

Сборка создаёт отдельную папку с полным деревом производственных зависимостей, включая вложенные зависимости pnpm. Исходные `node_modules` не изменяются; публикация отключена. После сборки обновляются локальные контрольные суммы установщика.

## Сборка нативного ядра

Для чистой копии проекта нужны Node.js 22+, Python 3.8+, Git и tar. Зависимости JavaScript должны быть установлены. Сборка использует переносимые Emscripten 4.0.15, CMake 3.30.5 и Ninja 1.12.1; системный PATH не меняется.

```powershell
node scripts/ocr-native/setup-toolchain.cjs --python "C:/path/to/python.exe" --build-root "D:/tvs-ocr-native-build"
node scripts/ocr-native/prepare-dependencies.cjs
node scripts/ocr-native/prepare-core-source.cjs
node scripts/ocr-native/build-dependencies.cjs
node scripts/ocr-native/build-core.cjs --output vendor/tesseract-core
npm run build
```

Путь Python и каталог сборки задаются для конкретного компьютера. Каталог сборки должен иметь ASCII-путь: туда копируется встроенный PDF-шрифт для обхода ошибки Unicode в упаковщике Emscripten 4.0.15. При повторной сборке с готовыми исходниками и prefix достаточно команды build-core; prepare-core-source сохраняет существующие исходники и отказывается их перезаписывать. SDK cache остаётся на диске SDK для совместимости Emscripten 4.0.15 с Windows; объекты и prefix могут находиться на другом диске. Побайтовое совпадение сборок в произвольных каталогах не обещается.

## Данные и обновления

Рабочая база находится в пользовательской папке `Документы\ДиспетчеризацияАвто_ТВС` по умолчанию. Установщик приложения не включает пользовательскую базу. Перед крупным обновлением сохраните актуальную резервную копию из настроек программы.

Для сетевого режима создайте персональные учётные записи на сервере и передайте каждому сотруднику его токен. После настройки персонального доступа общий ключ отключается. HTTPS требует сертификат и закрытый ключ сервера; клиент проверяет доверие сертификату. HTTP клиент разрешён только в локальной сети. Сервер и клиенты должны использовать одну версию.

Автообновление проверяет SHA256 из доверенного HTTPS манифеста. Локальная сборка не публикует выпуск на GitHub. Установщик пока без сертификата издателя. Полная приёмка рабочих сценариев отдельно не проводилась.

Список выпусков хранится в [`assets/CHANGELOG.md`](assets/CHANGELOG.md). Версию и ссылку автообновления задаёт [`version.json`](version.json).
